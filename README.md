## 项目简介

本工具解决一个很朴素的问题：Amazon Seller Central 的 FBA 退货列表 UI 有约 **1 万行的硬天花板**，且后台录入存在延迟，单日新增条数波动极大。手工每天去截图、复制、去重既不现实也不可靠。

于是把整套操作脚本化：借助紫鸟（ziniao）浏览器 + ZClaw Bridge 走 CDP 控制，在卖家后台内「借页面自身请求」抓取数据，用**游标增量**模式只拉取「上次之后」的新退货，按「订单号 + ASIN」去重后追加到 `master.csv`，并产出当日增量日报。

设计铁律（来自用户要求）：

- **全手动可控、可暂停、显式 kill switch**；AI 不自动对 live Amazon 账号点击。
- 失败不重试死循环，记录原因，次日自动续跑（去重 + 游标保证幂等）。

---

## 功能特性

- **游标增量**：以 `daily_state.json` 中的 `cursorOrderId`（上次最新 Order ID）为游标，从列表顶部往下翻，重新遇到游标即停止，其上方全为新增。天然适配「每日新增不固定为 1000 行」的真实场景。
- **幂等去重**：按「订单号 + ASIN」组合去重，一条退货事件只记一次；重复运行不会重复落盘。
- **五道防线**：读入前 / 落盘前的多重保安检，杜绝半截写入、二进制污染、列数错乱。
- **自愈快照**：每次成功写盘后更新 `master.csv.good.bak`，主表损坏时自动回滚。
- **日报按退款日分布命名**：文件名携带退款日与条数，一眼可判数据新鲜度。
- **配置外部化**：店铺、CLI 路径、Marketplace URL 全部来自 `config.js` / 环境变量，脚本零硬编码敏感信息。
- **可复用分发**：已 skill 化并开源（见[相关链接](#相关链接)），定时任务跑的是本目录真身。

## 架构与数据流

```
┌─────────────────────────┐
│  Amazon Seller Central   │  https://sellercentral.amazon.com/fba-return
│  (FBA Returns 列表, UI)  │
└────────────┬────────────┘
             │  紫鸟浏览器 (川鹏2号) + ZClaw Bridge (CDP)
             │  借页面自身请求 (注入 recordsPerPage=1000, 触发 change)
             ▼
┌─────────────────────────┐
│  set_filter.js          │  设 LAST_7_DAYS (REFUND_DATE_FILTER_GROUP)
│  inject 1000 / extract   │  extract_full.js 逐页结构化取数 (13 列)
│  _full.js / next.js      │  next.js 翻页
└────────────┬────────────┘
             │  page exec 返回 13 列行
             ▼
┌─────────────────────────┐
│  daily_pull.js          │  游标增量: 从顶部往下翻, 命中 cursorOrderId 即停
│                         │  按 订单号+ASIN 去重
└────────────┬────────────┘
             │
     ┌───────┴────────┬──────────────┐
     ▼                ▼              ▼
 master.csv      daily_YYYY-MM-DD   daily_state.json
 (累计去重主表)   (当日新增日报)     (游标 + 计数)
```

> 注：UI 表格服务端约 1 万行封顶（1000/页 → 第 10 页卡死；500/页 → 第 21 页卡死），且日期筛选只有 6 个预设 radio、无自定义起止区间。因此 **UI 路线最多只拿最新 ~1 万条，全量历史必须走 SP-API 官方 Customer Returns 报表**。本流水线定位为「每日增量 + 7 天窗口补登」，非全量回填。

## 核心机制：全窗扫描 + 去重

> 早期版本用「命中游标即停」做增量边界，**已废弃**（下方「为什么改」）。

现行策略：筛选本就按**退款日**限定 7 天窗口（`LAST_7_DAYS`），所以**把整窗翻完**即可，不再用游标当停止条件：

```
设筛选 LAST_7_DAYS → 注入 1000 行/页
        │
        ▼ 从第 1 页往下翻，直到「无下一页」
  逐页 extract_full 提取 → 全部收集
        │
        ▼ 按「订单号 + ASIN」与 master.csv 去重
  仅新增行落盘（master 台账）+ 当日日报分片（Title 脱敏）
```

- **游标仍然更新**（`daily_state.json.cursorOrderId` = 本次抓到的最顶部 Order ID），但**只作日志标记**，不再决定何时停止翻页。
- **为什么改**：退货列表按授权/订单时间排序，而退款日刚进 7 天窗口的记录，其排序键可能更老 → 会排在游标**下方**而被漏抓。整窗重扫可闭合该缺口。
- **代价**：单次运行从 2 页变为约 10 页（耗时约翻倍）。这是刻意用时间换完整性。
- **去重保证幂等**：整窗重扫会把大量旧行再拉一遍，全部由去重挡掉，不会重复落盘。
- 退款日 **> 7 天**的迟到记录由独立的每周深扫（30 天）兜底。
- 单次 API 上限 1000 行/页 × 10 页 ≈ 1 万行，即 UI 硬天花板；`stuck=true` 表示在第 10 页卡住（未自然翻完）。

## 外发件脱敏：`Title` 列清空

日报分片会**上传到钉钉知识库**（外发），因此从 2026-09-18 起：

| 产物 | `Title` 列 | 说明 |
|------|-----------|------|
| `master.csv`（本地台账） | **保留原文** | 本地分析能力不牺牲 |
| `YYYY月D日导出增量数据_*.csv`（外发件） | **保留列头、清空内容** | 列数/列顺序/其他 12 列完全不变 |

- 开关：`FBA_KEEP_TITLE=1 node daily_pull.js` 可临时还原日报全文（本地排查用）。
- 回溯清洗历史日报：`node redact_title.js <file.csv> [...]`（幂等）。
- ⚠️ **不要**对 `master.csv` 执行 `redact_title.js` —— 本地台账应保留全文。
- 去重键（订单号 + ASIN）与日报文件名的退款日统计**均不受影响**。

## 五道防线（保安检）

| # | 位置 | 检查 | 不通过时 |
|---|------|------|----------|
| 1 | 读入 master | 主文件绝不能是 xlsx/二进制（历史曾因异常被写成 PK 压缩包） | 从 `good.bak` 自愈，失败则中止 |
| 2 | 读入 master | 表头必须是合法 13 列且等于约定 HEADER | 从 `good.bak` 自愈，失败则中止 |
| 3 | 落盘前 | 每一提取行必须是 13 列字符串 | 中止写入，绝不损坏 master |
| 4 | 落盘前 | 待写内容疑似二进制（PK 签名） | 中止写入 |
| 5 | 落盘前 | mtime 守护：运行期 master 被外部改动则放弃写入 | 放弃本次写入，保留外部好数据 |

额外：原子写入（先写 `.tmp` 再 `rename`）、写后 13 列校验、成功后更新 `good.bak` 快照。

## 日报命名规则

格式：`<北京时间 M月D日>导出增量数据_<MM-DD> (N 条) + <MM-DD> (M 条).csv`

- 统计维度 = **Refund Date（退款日）**，多天按日期升序、「 + 」连接；缺失归「未标注」排最后。
- 日期原本 `MM/DD/YYYY`，取 `MM-DD`；`/` 在 Unix 文件名是路径分隔符，必须换成 `-`。
- 超 180 字节自动降级为区间摘要 `08-26~09-01 (1663 条)`，防超文件名 255 字节上限。
- 同日重跑撞名时追加序号后缀（如 `(2)`），主表不受影响。

示例：`9月4日导出增量数据_09-02 (383 条) + 09-03 (1052 条).csv`

## 前置条件

- **紫鸟浏览器**（店铺：川鹏2号）必须已打开并登录。
- **ZClaw Bridge**（端口 9480/9481）必须运行，CDP 通道可用。
- 失败（浏览器未开 / 桥未连 / 超时）不要重试死循环，记录原因即可，次日自动续跑。

### 店铺可控性守卫（`store_guard.js`）

抓取完全依赖 CDP target。若店铺窗口是**用户在紫鸟客户端手动点开**的，而不是由**紫鸟 CLI** 拉起的，附着上去可能拿不到可用 `targetId`，导致空转/失败。因此两个抓取脚本（`daily_pull.js` / `pull_latest_raw.js`）在动手前统一调用 `ensureStore()` 过闸。

**核心思路：来源无关。** 不问"谁开的窗口"（不可靠），只验证"窗口是否可控且在正确页面"：

| 层级 | 判定 | 行为 |
|------|------|------|
| ① 硬门禁 | `visit_page` 必须返回非空 `targetId` | 拿不到 → 自动补救；仍拿不到 → 中止（exit 11） |
| ② 页面实测 | 注入 JS 检查：URL 含 `fba-return`、退货表或 `LAST_7_DAYS` 筛选器存在 | 不过 → 自动补救 |
| ③ 自动补救 | `store close` + 冷启动重开 + 重新验证（**仅一次**） | 仍不过 → **fail-closed 中止** |
| ④ 环境变量 | `FBA_FORCE_FRESH=1` 直接冷启动；`FBA_NO_REMEDIATE=1` 禁用补救 | 见左 |

> ⚠️ **为什么不用 `launchSource`**：实测 `store open` 在「全新拉起」与「复用已有窗口」两种情况下**都返回 `cli`**；`extract_data mode=store` 只返回 `running`、桥日志为空——无法证明该字段能区分「手动打开」。据此放行等于**假安全**，故已弃用，改为上面的来源无关方案。

> 紫鸟硬约束：F12 开发者模式被企业策略禁用 → 改用 `page exec` 注入脚本改 DOM / 钩 fetch；直接重放 `/fba-return/refresh` 会被 CSRF 挡（返回壳页非数据）→ 必须「借页面自身请求」：注入 `recordsPerPage=1000` 选项触发 change，再读渲染后的 DOM。

## 健康检查

固定三项，每次跑完核对：

1. **日报内部重复数**：应为 0。
2. **master 列数异常行**：应为 0（13 列校验）。
3. **日报 Refund Date 分布**：应集中在最近 1~2 天。

> 每日新增条数波动极大属正常，不看条数看日期。实测 9-01 仅新增 26 条、9-02 新增 1663 条（差 64 倍），体检后确认健康。根因是 **Amazon 退货列表存在录入延迟**：某退款日的记录并非当天全部进入列表，往往次日补齐 → 单日新增少 ≠ 漏抓，次日会自然补登。

## 已知限制

- **UI 上限 ~1 万行**：只覆盖最新窗口，全量历史（>1 万条）必须走 SP-API 官方 Customer Returns 报表。
- **日期筛选无自定义区间**：仅 6 个预设 radio，故「按任意日期窗口切片」不可行 → 只能整窗重扫 + 去重。
- **Authorization Date 跨数周是正常的**：授权早、退款晚；筛选器是 `REFUND_DATE_FILTER_GROUP`，**绝不可用 Authorization Date 判断增量边界**。
- **退款列表会分批补登（最易误判的一条）**：同一退款日的记录会在之后 **2~4 天**陆续出现在列表里。实测闭环：

  | 退款日 | 首次进日报 | 最终入库 | 首次完整度 |
  |--------|-----------|---------|-----------|
  | 09-14 | 25 | 1583 | 1.6% |
  | 09-15 | 945 | 1300 | 72.7% |
  | 09-16 | 25 | 1187 | 2.1% |

  → **日报里最新 1~2 个退款日是临时值，不可当最终数用**；否则会误以为"数据一直在变/出问题"。
- **UI ~1 万行硬天花板**：1000 行/页 × 10 页封顶，窗口内排名 1 万行之后的记录单次扫不到，靠每周深扫兜底。
- 单次运行耗时**与页数成正比、与行数无关**：10 页稳定约 130~150 秒，其中约 78% 是固定等待（翻页间隔各 8~10 秒），实际取数仅约 30 秒。

## 判读要点

- 看「退款日分布」而非「条数」判断数据新鲜度。
- 全窗扫描模式下**每天固定 10 页**、`hitCursor` 每天为真均属正常（游标只作标记）。
- `stuck=true` 才算触达 UI 上限（第 10 页首页主键未变 = 卡死）；**仅 1 页也报 `stuck=true` 时多为 false positive**（窗口内本就只有当日新增、翻页后无下一页）。
- 日报里最新 1~2 天条数偏低是**补登未完成**，不是漏抓；次日会自动补齐。
- master 总条数只增不减（去重保证）；日报为当日新增切片，且 **`Title` 列已清空**（外发件脱敏）。
